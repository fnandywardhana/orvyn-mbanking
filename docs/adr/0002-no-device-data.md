# The app collects no data from the phone it runs on

The owner requires that ORVYN takes nothing from the tester's device: only what the Customer types reaches the server. So identity photos taken during Registration never leave the phone and are deleted after the step, voice input uses only the on-device recognizer, the Registered Device is a random code generated at install (never IMEI, Android ID or advertising ID), images are picked through the system Photo Picker without storage permission, and the app ships with no analytics, crash reporter or ad SDK. Firebase Cloud Messaging is the single exception, accepted by the owner, because push notifications need its random token. This is a constraint that is invisible in the code, so a future change that adds an SDK or permission "for convenience" would quietly break it; the build fails if the merged manifest contains any permission outside the approved list.
